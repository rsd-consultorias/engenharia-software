# Plano de Diagnóstico para Equipe Técnica 

## Objetivo
Avaliar o nível técnico, comportamental e estratégico da equipe que desenvolve aplicações web, utilizando tecnologias específicas e práticas modernas.

## 1. Mapeamento de Competências Técnicas
Crie uma matriz com os principais pilares técnicos exigidos pelo cliente e pela stack usada:

| **Área técnica** | **Competência Avaliada**                 | **Nível** | **Observações**                                   |
|------------------|------------------------------------------|-----------|---------------------------------------------------|
| Backend          | Java, Spring Boot, REST APIs             |           |                                                   |
| Backend          | C#, .Net Core, REST APIs                 |           |                                                   |
| Frontend         | Typescript, React, Next                  |           |                                                   |
| DevOps/Cloud     | CI/CD, Docker, Kubernetes, AWS/GCP/Azure |           |                                                   |
| Testes           | JUnit, Cypress,                          |           |                                                   |
| Arquitetura      | Microserviços, escalabilidade, segurança	|           |                                                   |
| Documentação     | Swagger, OpenAPI, README técnicos	      |           |                                                   |

- **Pontuação**
  - **[ 0 ]** - Não conheço nada
  - **[ 1 ]** - Conheço algo, mas não sei fazer nada
  - **[ 2 ]** - Se tiver algo pronto, consigo copiar
  - **[ 3 ]** - Consigo criar do zero, mas não conheço a fundo
  - **[ 4 ]** - Consigo resolver a maioria dos problemas que surgirem

## 2. Diagnóstico Comportamental e de Colaboração
Avalie aspectos que impactam a produtividade e a saúde da equipe:

| Comportamento        |	Indicador de Avaliação                      | Método de Coleta         |
|----------------------|----------------------------------------------|--------------------------|
| Comunicação          | Clareza em reuniões, feedbacks, alinhamentos | 1:1s + pesquisa interna  |
| Colaboração          | Pair programming, revisão de código          | Observação + entrevistas |
| Autonomia            | Capacidade de resolver problemas sozinho     | Avaliação do líder       |
| Proatividade         | Sugestões de melhoria, antecipação de riscos | Histórico de iniciativas |
| Adaptação ao cliente | Entendimento de contexto e requisitos        | Feedback do cliente      |

## 3. Análise de Entregas e Qualidade
Avalie a consistência e qualidade das entregas:

- Velocidade de entrega: tempo médio por funcionalidade
- Taxa de retrabalho: bugs ou refações pós-entrega
- Cobertura de testes: percentual por projeto
- Aderência a padrões: uso de guidelines e boas práticas

## 4. Entrevistas Técnicas e 1:1s
Realize conversas individuais com foco em:

- Dores técnicas e operacionais
- Ambições de carreira
- Percepção sobre o cliente e os projetos
- Sugestões de melhoria

Use perguntas abertas como “O que você gostaria de dominar nos próximos 3 meses?” ou “Quais obstáculos técnicos você enfrenta com frequência?”
